# AI Image Detector

A production-grade system that detects whether an image was generated by an AI tool or is a real photograph. It combines four independent detection methods through a weighted ensemble to deliver reliable, explainable verdicts.

## Overview

AI Image Detector analyses any JPEG, PNG, or WEBP image and answers one question:

> **"Was this image created by an AI tool, or is it a real photograph?"**

It returns a verdict, a confidence score (0–100%), a risk level (Low / Medium / High), and plain-English signals explaining why the decision was made.

---

## Features

- **Four-method ensemble** — CNN classifier, frequency analysis, metadata inspection, and texture analysis run in parallel and are fused into a single score
- **Explainable results** — every verdict comes with human-readable signals
- **Adjustable weights** — tune each detector's contribution via sidebar sliders or environment variables
- **Streamlit web UI** — drag-and-drop image upload, live results, detector breakdown
- **FastAPI REST API** — programmatic access with API-key authentication and rate limiting
- **Docker support** — single `docker compose up` to run either the UI or the API
- **Custom model training** — train or fine-tune the CNN on your own AI-vs-real dataset
- **Prometheus metrics** — built-in observability endpoint
- **Structured logging** — `structlog`-powered JSON logs

## How It Works

### Detection Methods

| # | Detector | Default Weight | What It Checks |
|---|---|---|---|
| 1 | **CNN Classifier** | 45% | EfficientNet-B4 deep learning model scores the overall visual "feel" of the image |
| 2 | **Frequency Analysis** | 20% | FFT-based spectral scan detects GAN fingerprints and abnormal frequency distributions left by AI generation |
| 3 | **Metadata Analysis** | 20% | EXIF inspection for known AI tool signatures (Stable Diffusion, Midjourney, DALL-E, and 16+ others), missing camera data, and square AI-typical dimensions |
| 4 | **Texture Analysis** | 15% | Spatial coherence checks for micro-texture uniformity, abrupt blur transitions, and suspicious colour-channel correlations |

#### CNN Classifier (`app/models/cnn_classifier.py`)

Uses EfficientNet-B4 pre-trained on ImageNet via the `timm` library. The model outputs a probability in [0, 1] where 1 = AI-generated. Custom weights can be trained with `scripts/train.py` and are loaded automatically from `models/weights/`.

#### Frequency Analysis (`app/detectors/frequency.py`)

Converts the image to grayscale, applies a 2D Fast Fourier Transform, and inspects the radially-averaged power spectrum. Signals include: abnormal high-frequency roll-off, repeating spectral peaks, and insufficient fine-detail energy.

#### Metadata Analysis (`app/detectors/metadata.py`)

Reads EXIF tags using Pillow. Checks for:
- Software/tool fields matching a known AI tool list
- Absence of camera make/model/lens fields
- Image dimensions matching common AI output sizes (e.g., 512×512, 1024×1024)

#### Texture Analysis (`app/detectors/texture.py`)

Uses OpenCV to compute local binary patterns, Laplacian variance maps, Canny edge density, and per-channel colour correlations. Flags images whose textures are unnaturally uniform or whose blur distribution is inconsistent with optics.

---

### Ensemble Scoring

After all four detectors run, the **Ensemble Engine** (`app/detectors/ensemble.py`) combines their scores:

```
Final Score = (CNN × 0.45) + (Frequency × 0.20) + (Metadata × 0.20) + (Texture × 0.15)
```

The combined score is then calibrated and mapped to a verdict and risk level:

| Score Range | Risk Level | Verdict |
|---|---|---|
| 0.00 – 0.40 | Low | Likely Authentic |
| 0.40 – 0.70 | Medium | Uncertain |
| 0.70 – 1.00 | High | Likely AI-Generated |

The classification threshold (default 0.50) determines the binary verdict.

### Image Flow

```
Upload image (JPEG / PNG / WEBP, max 10 MB)
        ↓
Size and format validation
        ↓
    ┌─────────────────────────────────────────┐
    │  All 4 detectors run in parallel        │
    │                                         │
    │  ① CNN Classifier    → score 0 – 1      │
    │  ② Frequency Check   → score 0 – 1      │
    │  ③ Metadata Check    → score 0 – 1      │
    │  ④ Texture Check     → score 0 – 1      │
    └─────────────────────────────────────────┘
        ↓
Ensemble engine fuses scores with weights
        ↓
Final verdict + confidence + risk level + signals
        ↓
Displayed in the UI  —OR—  returned as JSON via API
```

## Quick Start

### Prerequisites

- Python 3.11 or newer  **OR**  Docker + Docker Compose

---

### Option 1 — Local Python

```bash
# 1. Clone the repository
git clone https://github.com/tusshaarpd/AI_Image_detector.git
cd AI_Image_detector

# 2. Install dependencies
pip install -r requirements.txt

# 3. Launch the Streamlit web UI
streamlit run streamlit_app.py
```

Open **http://localhost:8501** in your browser. Drag and drop any image to analyse it.

---

### Option 2 — Docker

No Python installation required.

```bash
# Clone the repository
git clone https://github.com/tusshaarpd/AI_Image_detector.git
cd AI_Image_detector

# Run the Streamlit UI
docker compose up streamlit
```

Open **http://localhost:8501**.

To run the FastAPI REST API instead:

```bash
docker compose up api
```

API available at **http://localhost:8000**. Interactive docs at **http://localhost:8000/docs**.

## REST API

Start the API server and send requests with your API key:

```bash
# Start
docker compose up api

# Send an image file
curl -X POST http://localhost:8000/api/v1/detect/upload \
  -H "X-API-Key: changeme-in-production" \
  -F "file=@photo.jpg"
```

Example response:

```json
{
  "is_ai_generated": true,
  "confidence_score": 0.82,
  "risk_level": "High",
  "signals_detected": [
    "No camera metadata present",
    "Square dimensions typical of AI output: 1024x1024",
    "CNN classifier: high AI probability (0.91)"
  ],
  "model_version": "1.0.0"
}
```

The API uses API-key authentication (`X-API-Key` header) and rate limiting (default 100 requests/minute). Set your key via the `API_KEY` environment variable before deploying to production.

Full interactive docs: **http://localhost:8000/docs**

## Configuration

Settings are loaded from environment variables or an optional `.env` file in the project root.

| Variable | Default | Description |
|---|---|---|
| `MODEL_NAME` | `efficientnet_b4` | Backbone architecture for the CNN classifier |
| `DEVICE` | `cpu` | Set to `cuda` to use a GPU |
| `MAX_IMAGE_SIZE_MB` | `10` | Maximum accepted image size |
| `CONFIDENCE_THRESHOLD` | `0.5` | Score cutoff for the AI-generated verdict |
| `WEIGHT_CNN` | `0.45` | CNN detector weight in the ensemble |
| `WEIGHT_FREQUENCY` | `0.20` | Frequency detector weight |
| `WEIGHT_METADATA` | `0.20` | Metadata detector weight |
| `WEIGHT_TEXTURE` | `0.15` | Texture detector weight |
| `API_KEY` | `changeme-in-production` | Secret key for REST API authentication |
| `LOG_LEVEL` | `INFO` | Logging verbosity (`DEBUG`, `INFO`, `WARNING`, `ERROR`) |
| `RATE_LIMIT` | `100/minute` | API rate limit per client |

Example `.env` file:

```env
DEVICE=cuda
MAX_IMAGE_SIZE_MB=20
API_KEY=my-secret-key
LOG_LEVEL=DEBUG
```

Ensemble weights can also be adjusted live in the Streamlit sidebar without restarting the app.

## Training a Custom Model

The CNN classifier works out-of-the-box using ImageNet pre-training, but accuracy improves significantly when fine-tuned on a labelled AI-vs-real dataset.

### 1. Organise your dataset

```
data/
  train/
    ai/       ← AI-generated images
    real/     ← Real photographs
  val/
    ai/
    real/
```

### 2. Run the training script

```bash
python scripts/train.py \
  --data_dir data/ \
  --epochs 20 \
  --batch_size 32
```

### What happens during training

1. Images are augmented with random flips, rotations, and colour jitter.
2. The model trains for the specified number of epochs.
3. Validation accuracy is checked after each epoch; the best checkpoint is saved automatically.
4. A training history file is written for later inspection.
5. The saved weights are loaded automatically on the next app start — no extra steps needed.

Trained weights are stored in `models/weights/`.

## Why Four Detectors?

No single method is sufficient on its own:

- The **CNN** excels at overall visual patterns but can be confused by unusual real photos.
- **Frequency analysis** reliably catches GAN fingerprints but is less effective against modern diffusion models.
- **Metadata** is definitive when an AI tool has left its name in the file, but many images arrive stripped of metadata.
- **Texture analysis** spots smoothness and uniformity anomalies that other methods miss, but cannot detect frequency artefacts.

Combining all four with a weighted ensemble covers each method's blind spots and produces a significantly more reliable result than any individual check.
