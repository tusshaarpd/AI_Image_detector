# AI Image Detector — Implementation Details

## Overview

A multi-signal AI image detection system that determines whether an image was generated by AI tools (Stable Diffusion, Midjourney, DALL-E, etc.) or is an authentic photograph. The system combines **four independent detection methods** through a weighted ensemble with Platt-scaling confidence calibration.

Two interfaces are provided:
- **Streamlit UI** — interactive web app for drag-and-drop analysis (primary)
- **FastAPI REST API** — programmatic access for integration into pipelines

```bash

pip install -r requirements.txt
```

## Detection Methods

### 1. CNN Classifier (`app/models/cnn_classifier.py`)

| Aspect | Detail |
|--------|--------|
| Architecture | EfficientNet-B4 (default) or ResNet-50 |
| Input | 224 × 224 RGB, ImageNet-normalised |
| Output | Single logit → sigmoid → probability |
| Weights | Pretrained ImageNet; replace with fine-tuned weights at `models/weights/{model_name}_detector.pth` |

**How it works:**

1. The uploaded image is resized to 224×224 and normalised with ImageNet statistics.
2. The model produces a single logit; sigmoid converts it to a probability ∈ [0, 1].
3. The score is annotated with an interpretation signal (high / moderate / uncertain / likely-real).

Without fine-tuned weights the model relies on pretrained ImageNet features, which still provide meaningful feature extraction but should be fine-tuned on an AI-vs-real dataset for production accuracy.

### 2. Frequency Analysis (`app/detectors/frequency.py`)

Analyses the **FFT (Fast Fourier Transform)** power spectrum to detect GAN fingerprints.

Three sub-analyses:

| Sub-analysis | What it detects | Key threshold |
|---|---|---|
| **Radial power spectrum** | Abnormal spectral drop-off — GANs produce steeper roll-off | high/low frequency ratio < 0.15 |
| **GAN fingerprint peaks** | Periodic peaks in the frequency domain left by upsampling layers | peak ratio > 0.5% of spectrum |
| **High-frequency energy** | AI images lack fine high-frequency detail | outer-25% energy < 2% of total |

**How it works:**

1. Convert image to 256×256 grayscale.
2. Compute 2D FFT and shift zero-frequency to centre.
3. For spectral drop-off: compute radial mean power profile, compare low-freq vs high-freq halves.
4. For GAN fingerprints: remove DC, threshold at mean + 4σ, count outlier peaks.
5. For HF energy: mask outer 25% annulus, compute energy ratio.

### 3. Metadata Analysis (`app/detectors/metadata.py`)

Inspects **EXIF metadata** for signals that are present in real camera photos but absent in AI outputs.

| Check | What it looks for | Score impact |
|---|---|---|
| AI tool signatures | 19 known tools (Stable Diffusion, Midjourney, DALL-E, …) in any EXIF value | 1.0 (definitive) |
| Camera metadata | Make, Model, FocalLength, ExposureTime, … (15 tags) | 0.1 (rich) → 0.7 (none) |
| No EXIF at all | Complete absence of metadata | 0.6 |
| Editing software | Photoshop, GIMP, Lightroom, Capture One | 0.2 |
| Format hints | Square power-of-2 dimensions (512×512, 1024×1024, …) | 0.3 |

### 4. Texture Analysis (`app/detectors/texture.py`)

Examines **spatial micro-textures and coherence** using computer-vision features.

| Sub-analysis | Technique | AI artefact detected |
|---|---|---|
| Texture variance | Coefficient of variation across 32 px blocks | Unnaturally uniform textures |
| Blur consistency | Laplacian variance in overlapping 64 px blocks | Abrupt blur transitions (Q75/Q25 ratio) |
| Edge coherence | Sobel gradients → edge angle entropy (36 bins) | Low edge direction diversity |
| Colour correlation | Pearson R–G, R–B, G–B channel correlation | Abnormally high inter-channel correlation (> 0.97) |

## Ensemble Decision Engine (`app/detectors/ensemble.py`)

Combines the four detector scores into a single calibrated confidence.

**Steps:**

1. **Weighted sum:**  `raw = 0.45·CNN + 0.20·Freq + 0.20·Meta + 0.15·Texture`
2. **Platt scaling:**  `calibrated = σ(a · raw + b)`  where σ is sigmoid, default a=1, b=0
3. **Classification:**  `is_ai_generated = calibrated ≥ threshold` (default 0.5)
4. **Risk level:**
   - ≤ 0.40 → **Low**
   - 0.40–0.70 → **Medium**
   - \> 0.70 → **High**
5. **Signal aggregation:** all non-empty signal strings from every detector are collected.

Weights and thresholds are adjustable through the Streamlit sidebar at runtime, or via environment variables for the API.

## Streamlit Application (`streamlit_app.py`)

### Features

- **Drag-and-drop upload** for JPEG, PNG, WEBP images (up to 10 MB)
- **Side-by-side layout:** uploaded image on the left, verdict + metrics on the right
- **Detector breakdown:** per-detector progress bars and signal lists
- **Adjustable ensemble weights** via sidebar sliders (auto-normalised)
- **Adjustable classification threshold** via sidebar slider
- **Raw JSON view** in collapsible expander
- **Cached model loading** via `st.cache_resource` — the CNN model loads once and persists across reruns

### How it connects to the detection pipeline

```python
# Each heavy component is loaded once via @st.cache_resource
@st.cache_resource(show_spinner="Loading CNN model…")
def load_cnn_classifier() -> CNNClassifier:
    return CNNClassifier()

# The detection function calls each detector directly
def run_detection(image: Image.Image) -> dict:
    metadata_result = load_metadata_detector().analyze(image)
    frequency_result = load_frequency_detector().analyze(image)
    texture_result = load_texture_detector().analyze(image)
    cnn_result = load_cnn_classifier().predict(image)
    decision = load_ensemble().decide(...)
    return {"decision": decision, "individual": {...}, "elapsed_seconds": ...}
```

The Streamlit app uses the **same detector classes** as the FastAPI API — zero code duplication.

## Training (`scripts/train.py`)

Fine-tune the CNN classifier on your own AI-vs-real dataset.

### Data layout

```
data/
  train/
    ai/       ← AI-generated images
    real/     ← Real photographs
  val/
    ai/
    real/
```

### Run training

```bash
python scripts/train.py \
  --data_dir data/ \
  --epochs 20 \
  --batch_size 32 \
  --lr 1e-4 \
  --device cuda
```

### What the script does

1. Loads `ImageFolder` datasets with train-time augmentation (flip, rotation, colour jitter, affine).
2. Creates the same EfficientNet-B4 (or ResNet-50) architecture used at inference.
3. Trains with **BCEWithLogitsLoss**, **AdamW** optimizer, **cosine annealing** LR schedule.
4. Saves the best model weights (by val accuracy) to `models/weights/{model_name}_detector.pth`.
5. Writes `training_history.json` with per-epoch metrics.

Once training completes, the saved weights are **automatically picked up** by both the Streamlit app and the API on next restart — no config changes needed.

## Configuration

All settings live in `app/core/config.py` and can be overridden via **environment variables** or a `.env` file.

| Variable | Default | Description |
|---|---|---|
| `MODEL_NAME` | `efficientnet_b4` | CNN architecture (`efficientnet_b4` or `resnet50`) |

## Key Design Decisions

1. **Ensemble over single model** — No single detector is reliable alone; combining CNN + frequency + metadata + texture gives robust coverage across different generation techniques.
2. **Platt scaling** — Raw weighted scores are passed through a sigmoid calibration layer so the output can be interpreted as a true probability.
3. **Modular detectors** — Each detector is a standalone class with an `analyze(image) → {score, signals}` interface, making it easy to add new detectors or swap implementations.
4. **Dual interface** — Streamlit for interactive use, FastAPI for programmatic integration, both sharing the same detection core.
5. **Cached model loading** — The CNN model (≈75 MB for EfficientNet-B4) loads once per process and is reused across all requests/reruns.
6. **Explainability signals** — Every detector produces human-readable signal strings that explain *why* the score is what it is, shown directly in the UI.
